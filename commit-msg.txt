feat: v0.10.0 — spatial-awareness layer (scene_state, pick, place_on, objects_in_region)

Closes the "AI can't relate what it sees to coordinates" gap. The screenshot was
a flat PNG with no spatial grounding; now the AI can map the viewport to world
coordinates and back. Server-only — each tool is a canned read-only Luau dispatch
through the existing runLuau op (no plugin change, plugin .rbxm stays 0.8.0),
same pattern as importing.ts.

- scene_state (read): camera intrinsics + curated visible objects, each with
  world pos/orientation/size AND on-screen pixel coords via WorldToScreenPoint.
  Grounds a screenshot ("object X at screen (px,py) = world (x,y,z)"). Models
  taken as one bbox unit; closest-first; bounded shallow walk (maxDepth, 4000-cap).
- pick (read): ViewportPointToRay + Raycast from a screen point (x/y, nx/ny, or
  center) → hit instance + model ancestor + world pos + surface normal + distance.
  Powers identify + tracing. Include/Exclude filters.
- place_on (write): raycast to a surface (screen point / onTarget top / ground),
  sit the object FLUSH via OBB half-extent offset along the normal, optional
  alignToNormal + grid snap; dryRun returns the CFrame. Part→CFrame, Model→PivotTo
  (bbox-center flush), one undo via ChangeHistoryService.
- objects_in_region (read): GetPartBoundsInBox/Radius / around-instance query.

Architecture: canned Luau runs via loadstring (no `script` global) so it uses
primitive APIs + an inlined path resolver only; returned tables auto-encode via
the handler's Serialize.encodeDeep. The three read tools dispatch FIXED read-only
code and stay visible in TUFAN_READONLY; place_on is in WRITE_TOOLS. scene_state
+ pick added to CORE_TOOLS.

72 → 76 tools (38 write / 38 read-visible). tsc clean; smoke shows 76; readonly
smoke shows 38 with place_on hidden + the read trio present. spatial-e2e.mjs added.
Docs (README/server-README/ISSUES/LAUNCH/MARKET_COMPARISON) updated.
