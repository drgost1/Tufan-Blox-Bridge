# MCP Spec 2026-07-28 — Compatibility Audit (phase A, v0.15.0)

Date: 2026-08-15
Scope: server (TypeScript, stdio MCP server + internal Express bridge for the Studio plugin).

## What the 2026-07-28 spec changes (summary)

- `initialize` / `initialized` handshake retired; per-request `_meta` carries protocol/client version.
- `Mcp-Session-Id` header retired (stateless routing).
- HTTP+SSE transport deprecated (Streamable HTTP only).
- Roots / Sampling / Logging deprecated in favor of MRTR.
- New `server/discover` RPC.

## What applies to this server

**Nothing yet — and that's expected.** The 2026-07-28 spec is implemented by the
**split v2 packages** (`@modelcontextprotocol/server`, `/client`, `/core` 2.0.0, published
2026-07-27). The legacy monolith `@modelcontextprotocol/sdk` tops out at **1.30.0** and still
speaks the `initialize`-handshake era (`LATEST_PROTOCOL_VERSION = 2025-11-25`).

### SDK bump landed: ^1.29.0 → ^1.30.0

[1.30.0 release notes](https://github.com/modelcontextprotocol/typescript-sdk/releases/tag/1.30.0)
(full changelog v1.29.0...1.30.0) — a maintenance release, no breaking API changes for our usage
(`McpServer` + `registerTool` + zod + `StdioServerTransport`):

- `fix(server): prioritize zod issues and format them` — validation error text only.
- `fix: support Zod 3.25 method literals` — we're on zod ^3.24.1, unaffected.
- `v1 stdio buffer limit` — new receive-side buffer cap on the stdio transport. Our tool outputs
  are already capped (datastore 100 KB, cloud_luau 60 KB); no change needed.
- `Validate Content-Type by parsed media type` + SSE keep-alive fixes — Streamable HTTP server
  transport only. We don't serve MCP over HTTP: the Express bridge is the Studio plugin's
  long-poll channel, not an MCP transport, so it is untouched (and untouched for spec reasons).
- CI / dependency-hardening changes — no runtime impact.

`tsc` clean on 1.30.0; `node smoke.mjs` lists all **83 tools** over stdio. Zero code changes
required by the bump.

## Deferred (tracked for a later milestone)

- **v2 SDK migration** (`@modelcontextprotocol/server@2.0.0` + codemod
  `npx @modelcontextprotocol/codemod v1-to-v2`): real 2026-07-28 compliance requires the split
  packages (Node 20+). Defer until the v2 line has ecosystem bake time and client support for the
  stateless spec is widespread; the 1.x monolith is still the npm `latest` line and fully supported.
- **MRTR for Roots/Sampling/Logging**: we don't use these capabilities at all — nothing to migrate.
- **`server/discover`**: v2-only; arrives with the SDK migration.
